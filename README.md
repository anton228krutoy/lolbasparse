# lolbas_detections.py — сбор правил детектирования LOLBAS

## Назначение
- Скачивает правила детектирования (Sigma, Splunk, Elastic и др.) для всех утилит, скриптов и библиотек из проекта [LOLBAS](https://lolbas-project.github.io).
- Привязывает каждое правило к конкретной утилите и раскладывает их по папкам.
- Строит общий индекс связей «утилита → правило → локальный файл».

## Требования и запуск
- Python 3.10+ и библиотеки: `pip install requests pyyaml`
- Запуск со всеми категориями: `python lolbas_detections.py`
- Параметры:
  - `-o / --out` — папка вывода (по умолчанию `lolbas_detections`)
  - `-w / --workers` — число потоков загрузки (по умолчанию 16)
  - `-c / --category` — только указанные категории (`Binaries`, `Libraries`, `OtherMSBinaries`, `Scripts`); флаг можно повторять
- Пример: `python lolbas_detections.py -o out -w 8 -c Binaries -c Scripts`

## Источник данных
- HTML-страницы скрипт не парсит, а берёт данные из официального JSON API: `https://lolbas-project.github.io/api/lolbas.json`
- В API у каждой записи есть поля `Name`, `Category`, `Commands`, `Full_Path`, `Detection` и др.
- Поле `Detection` содержит список пар вида `{"Sigma": url}`, `{"Splunk": url}`, `{"Elastic": url}`, `{"IOC": "текст"}`.

## Алгоритм
1. Загружается JSON со всеми записями LOLBAS.
2. Если задан `-c`, записи фильтруются по категориям.
3. Записи обрабатываются параллельно (`ThreadPoolExecutor`).
4. Для каждой записи:
   - создаётся папка `Категория/Утилита/`;
   - сохраняется сама запись LOLBAS в `lolbas_entry.yml`;
   - поле `Detection` делится на две группы:
     - **текстовые IOC** (не ссылки) идут в `iocs.txt`;
     - **ссылки** обрабатываются дальше.
5. Каждая ссылка проверяется функцией `to_raw_url()`:
   - `github.com/.../blob/...` преобразуется в `raw.githubusercontent.com/...`;
   - ссылки на файлы с расширениями `.yml .yaml .toml .json .kql .spl .xml .txt` скачиваются;
   - всё остальное (блоги, документация, папки `/tree/`) записывается в `other_links.txt`.
6. Скачанное правило кладётся в подпапку по типу: `sigma/`, `splunk/`, `elastic/` и т.д.
7. В конце формируются `index.csv`, `failed.txt` и итоговая статистика.

## Файлы в выводе
| Файл | Где | Содержимое |
|---|---|---|
| `lolbas_entry.yml` | папка утилиты | полная запись LOLBAS: описание, команды, пути, ресурсы |
| `iocs.txt` | папка утилиты | текстовые признаки из `Detection`, строки вида `[IOC] ...` |
| `other_links.txt` | папка утилиты | ссылки, по которым нечего скачать как файл правила |
| `index.csv` | корень | все связи: `category, tool, type, source_url, local_file, status` |
| `failed.txt` | корень | ссылки на правила, которые не удалось скачать |

- `iocs.txt`, `other_links.txt` и `failed.txt` создаются, только если в них есть что записать.

## Статусы в index.csv
- `ok` — правило скачано, путь указан в `local_file`.
- `link_only` — ссылка не на файл, сохранена в `other_links.txt`.
- `failed` — файл не скачался (обычно 404), запись попадает в `failed.txt`.

## Технические детали
- **Кеш загрузок:** одно правило часто привязано к нескольким утилитам; оно скачивается один раз, а копия кладётся в папку каждой утилиты.
- **Потокобезопасность:** у каждого потока своя `requests.Session`, доступ к кешу защищён `threading.Lock`.
- **Имена файлов:** недопустимые символы заменяются на `_`; если у разных правил совпадает имя, добавляется суффикс `_1`, `_2` и т.д.
- **Устойчивость:** ошибка одной записи не останавливает весь прогон; таймаут запроса 30 секунд.

## Ограничения
- Многие ссылки в LOLBAS указывают на ветку `master`, а правила в репозиториях (особенно SigmaHQ) переименовывают и переносят. Часть ссылок поэтому окажется в `failed.txt`, и такие правила проще найти по имени в локальном клоне `SigmaHQ/sigma`.
- Скачиваются только прямые ссылки на файлы; содержимое статей и папок репозиториев не загружается.
- Архив скрипт не создаёт. Упаковать результат можно вручную (`zip -r lolbas.zip lolbas_detections`) или добавить флаг `--zip` через `shutil.make_archive`.
